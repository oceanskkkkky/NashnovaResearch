# 微信公众号付费新闻订阅服务——完整实现方案

> 生成日期：2026-08-22
> 业务流程：关注公众号 → 开通包月会员 → 新新闻发布推送通知 → 点击跳转新闻站 → 会员身份阅读全文

---

## 0. 结论先行：三条路径

| | A. 小鹅通 SaaS 全托管 | B. SaaS 支付 + 自建新闻站 | C. 全自建（微信云托管） |
|---|---|---|---|
| 上线速度 | 认证服务号到位后 **2–3 天** | 约 2 周 | 约 3–4 周（含备案） |
| 年成本 | ≈ **14,100 元**（专业版 12,800 + 超级会员 988）+ 交易费 0.6%，年流水超 50 万部分另收 2% 服务费 | ≈ 7,000 + 服务器 200/月 | 服务器 100–300/月，**无流水抽成** |
| 会员/支付/推送 | 全部内置 | 支付与会员用 SaaS，内容站自建需打通（openid 映射），集成成本高 | 全部自主实现 |
| 内容形态自由度 | 受限于小鹅通图文组件，新闻站是小鹅通店铺页 | 自由 | 完全自由（可做 SEO、可迁移） |
| 适合场景 | 尽快验证市场、不想碰开发 | 少见，一般不推荐 | 新闻是长期主业、有基本开发能力（本工作区环境具备） |

**推荐**：
- 要最快上线、先验证付费意愿 → **路径 A**，随时可迁出（小鹅通支持导出用户数据）。
- 确定长期做、日均内容量大、在意品牌独立性 → **路径 C**，长期成本最低。
- 路径 B 的"打通"复杂度接近全自建但不获得自建的好处，**不建议**。

## 1. 公众号搭建（三条路径的前置条件，完全相同）

### 1.1 关键决策：必须注册「服务号」，不能是订阅号

| 能力 | 服务号（认证） | 订阅号 |
|---|---|---|
| 微信支付 | ✅ | ❌ |
| 模板消息 | ✅ | ❌ |
| 网页授权（静默识别用户） | ✅ | ❌ |
| 每月群发 | 4 次 | 每天 1 次（但无上述能力，无法闭环） |

付费业务闭环（支付 + 推送 + 网页鉴权）**只有认证服务号能做到**。

### 1.2 办理清单（按顺序，约 1–2 周）

1. **注册服务号**：mp.weixin.qq.com → 企业主体注册 → 服务号。
   - 个人主体无法认证服务号、无法开通微信支付，必须是企业/个体工商户。
2. **微信认证**：300 元/年，提交营业执照、对公账户信息，审核 1–3 个工作日。
   - 服务类目建议选「媒体资讯/IT科技」相关类目（影响可用模板库）。
3. **申请微信支付商户号**：认证通过后，在 mp 后台「广告与服务 → 微信支付」申请，需营业执照 + 对公账户或法人银行卡验证。标准费率约 0.6%。
4. **开发配置**（自建路径需要，SaaS 路径由小鹅通引导配置）：
   - 「设置与开发 → 公众号设置 → 功能设置」：配置**网页授权域名**（新闻站域名）、**JS 接口安全域名**。
   - 「设置与开发 → 基本配置」：获取 AppID/AppSecret，配置服务器 IP 白名单。
5. **开通模板消息插件**：「广告与服务 → 添加功能插件 → 模板消息」，选择行业类目后从模板库选用。
6. **绑定微信开放平台**（如后续要做小程序或多端）：open.weixin.qq.com 绑定公众号，获得 **UnionID** 打通能力。

## 2. 付费订阅系统（包月会员）

### 2.1 先说一个必须知道的现实：微信生态没有真正的「自动续费」

微信支付对普通商户**不开放代扣/签约扣款**（委托代扣需特约资质，基本不批）。所以：

- 「包月」实际形态是 **到期手动续费 + 到期前多通道提醒**。
- 小鹅通的会员、所有知识付费产品在微信内都是这个模式。
- 产品上必须做**续费提醒闭环**（见 2.3），否则续费率会很低。

### 2.2 路径 A：小鹅通

- 购买**专业版**（12,800/年）后可加购**超级会员**模块（988/年）。
- 配置：管理台 → 会员 → 新建会员卡 → 设定 30 元/月（建议同时挂季卡/年卡，年卡是主要营收）。
- 支付：小鹅通直连你自己的微信商户号，钱进你账户，小鹅通收 0.6% 交易手续费（走微信支付通道费）+ 流水超 50 万部分 2% 服务费。
- 会员有效期、到期提醒（模板消息 + 短信，短信另购）全部内置，零开发。

### 2.3 路径 C：自建

**支付流程**（JSAPI 支付，用户在微信内 H5 完成）：

```
H5 会员页点击"开通" 
→ 后端调用微信「统一下单」API（v3，JSAPI）返回支付参数
→ 前端 WeixinJSBridge 拉起支付 
→ 微信回调 notify_url（验签）→ 更新会员表 
→ 前端轮询/收到成功回调后刷新身份
```

**会员数据模型**（最小可用）：

```sql
CREATE TABLE member (
  openid     VARCHAR(64) PRIMARY KEY,   -- 公众号用户唯一标识
  unionid    VARCHAR(64),
  expire_at  DATETIME NOT NULL,         -- 会员到期时间
  level      TINYINT DEFAULT 1,
  created_at DATETIME,
  updated_at DATETIME
);

CREATE TABLE payment_order (
  out_trade_no VARCHAR(64) PRIMARY KEY,
  openid       VARCHAR(64),
  amount_fen   INT,                     -- 单位：分
  status       TINYINT,                 -- 0待支付 1成功 2已退款
  paid_at      DATETIME,
  raw_notify   TEXT                     -- 存回调原文，对账用
);
```

**续费逻辑**（未过期续费顺延，行业标准做法）：

```sql
UPDATE member SET 
  expire_at = GREATEST(NOW(), expire_at) + INTERVAL 1 MONTH 
WHERE openid = ?;
```

**到期提醒闭环**（后台定时任务）：
- 到期前 5/2/1 天：模板消息「会员到期提醒」（此类模板合规，属服务通知类）。
- 到期前 3 天：短信（需购买时收集手机号，见第 5 节）。
- 到期当天：公众号菜单/会员页展示「续费享优惠」。

**退款**：走微信支付商户平台退款 API，按 order 退款并同步扣减 expire_at。

### 2.4 iOS 购买风险（两条路径都要知道）

iOS 微信内「虚拟内容」支付历史上被苹果限制过。若被限制，表现是 iOS 用户拉不起支付。兜底方案：检测 UA，iOS 用户引导「复制链接到 Safari 打开完成支付」（Safari 内微信扫码或 H5 支付不受限）。上线后用 iOS 真机实测一笔。

## 3. 消息推送（合规是核心，先看约束再选通道）

### 3.1 微信推送通道的真实约束（2026 年现状）

| 通道 | 频率限制 | 关键约束 |
|---|---|---|
| 服务号群发图文 | **每月 4 次** | 发给全部粉丝（无法只发会员）；被判定营销的内容与模板消息合并计数 |
| 模板消息 | 日调用上限 10 万次（默认） | **只能发服务通知**。官方规范明文将「文章更新类通知」列为禁止的群发推广类；违规会被阶梯封禁接口甚至封号 |
| 小程序订阅消息 | 用户订阅一次只能推一条 | 新闻不在长期订阅类目，无法持续推送 |
| 企业微信 | 1v1 私聊无硬性次数限制 | 需引导会员添加你的企微客服/入会员群 |
| 短信 | 无限制 | 约 0.04–0.06 元/条，需手机号 |

### 3.2 合规推荐组合（日更新闻场景）

1. **日常更新（每日）**：模板消息「内容更新提醒」。
   - 合规基础：用户**购买了会员**，与账号主体存在服务关系（付费订阅服务本身即服务），这是知识付费行业（含小鹅通）普遍使用的通道。
   - 风险控制：每天最多 1 条；模板内不含营销话术（「新款优惠」这类必死）；提供退订入口；被用户投诉是主要风险源，频率宁低勿高。
2. **重磅独家（每月 ≤4 次）**：服务号群发图文，标题做钩子，正文/落地页只有会员能读全文 → 免费粉丝成为转化对象。
3. **实时性强的重磅推送**：企业微信会员群（见 3.3），无次数硬限制。
4. **保底通道**：短信，用于到期提醒和重要通知。

### 3.3 企业微信通道（建议尽早布局）

- 会员购买成功页放企微客服二维码（企微「联系我」二维码，可带渠道参数）。
- 后续新闻发布可 1v1 私聊推送或会员群推送，**不受模板消息类目和频率约束**，是目前付费资讯类产品（知识星球、财经资讯号）的主流做法。
- 企微好友还能做用户分层运营（到期未续用户单独触达）。

### 3.4 路径 C 的推送实现

- 发布新闻后，后台任务取出 `expire_at > NOW()` 的全部 openid，调用模板消息接口批量下发（注意接口每秒 QPS 限制，用队列限速，如每秒 50 条）。
- 模板消息 `url` 字段填新闻详情页链接（带 oauth 回跳），用户点击直达全文。
- 失败码 `43004`（用户拒收）记入退订表，30 天内不再下发。

## 4. 新闻网站

### 4.1 路径 A：小鹅通 H5 店铺

- 图文内容在小鹅通管理台发布，设为「会员专属」。
- 公众号菜单挂小鹅通店铺链接，用户点击 → 小鹅通自动微信授权 → 识别会员身份 → 可读/不可读。
- 零开发。缺点：URL 是小鹅通域名（可绑定自有域名，需备案+配置），页面样式受模板限制，无 SEO。

### 4.2 路径 C：自建 H5

**技术栈建议**：
- Next.js / Nuxt（SSR，若要搜索引擎收录）或任意前端框架 SPA（仅微信内传播则不需要 SSR）。
- 后端：Node/Python/Go 任一 + MySQL；部署在**微信云托管**（免鉴权配置打通微信，约 100–300 元/月起）或普通云服务器。

**用户身份验证（核心流程）**：

```
用户点击推送/菜单进入 https://news.example.com/a/123
→ 无有效 session：302 跳转微信 OAuth2：
   https://open.weixin.qq.com/connect/oauth2/authorize
     ?appid=APPID&redirect_uri=...&scope=snsapi_base&state=article_123
→ snsapi_base 静默授权（用户无感知，无需确认）
→ 微信 302 回跳带 code → 后端用 code 换 openid
→ 查 member 表：expire_at > now？
   → 是：签发 JWT（含 openid、is_member、过期时间，有效期 7 天），set-cookie，渲染全文
   → 否：渲染标题+摘要+付费墙（「开通会员阅读全文」按钮 → 会员购买页）
```

**安全要点**：
- **全文必须服务端按权限返回**，不能「前端返回了全文再隐藏 DOM」（右键查看源码即泄露）。
- JWT 里只放 openid 和会员标志，每次请求服务端再校验 `expire_at`（防止会员过期后 JWT 还有效——或 JWT 有效期 ≤ 剩余会员期）。
- 图片走防盗链（Referer 校验）或短时效签名 URL，防止正文被外站直接盗链。
- 高价值内容可选：正文分段渲染为图片（防复制，牺牲 SEO 和体验，按需启用）。
- 分享卡片：用 JSSDK `updateAppMessageShareData` 自定义分享标题/摘要/缩略图，摘要即钩子，驱动免费用户点进来撞付费墙转化。

**域名与备案（时间风险项）**：
- 大陆服务器必须 **ICP 备案**（约 2–3 周，企业备案需营业执照）。建议与服务号认证并行启动。
- 服务器放香港可免备案，但微信内访问速度与稳定性打折，且存在被限速风险，不建议主站用境外。

## 5. 用户体系打通

### 5.1 核心认知：openid 天然打通，不需要「账号绑定」

- 用户**关注**公众号 → 微信为其分配该公众号下的 openid。
- 用户**点击菜单/推送链接**进入 H5 → 网页授权（snsapi_base，静默）拿到的是**同一个 openid**。
- 因此：粉丝身份、支付身份、阅读身份三者天然统一，**用户全程无需注册、无需登录、无感知**。这是微信生态做付费订阅的最大工程红利。

### 5.2 多端扩展（如果将来做小程序/网站扫码登录）

- 公众号、小程序各自有不同的 openid，**UnionID** 才是跨端唯一标识。
- 需要在微信开放平台注册账号（300 元/年）并绑定公众号/小程序，同一用户在各端的 UnionID 相同。会员表以 UnionID 为主键更稳妥（初期用 openid 也够，加一列 unionid 备用）。

### 5.3 手机号收集（可选，用于短信提醒）

- H5 内无法调用微信手机号快捷授权（那是小程序能力），只能表单手动填写。
- 建议：购买成功页提示「填写手机号接收更新与到期短信」，给小额优惠券激励，自愿填写率通常 30–50%。

### 5.4 路径 A

小鹅通自动处理：关注公众号 + 授权进入店铺 + 支付，识别为同一用户，管理台可见统一用户档案。

## 6. 后台管理

### 6.1 路径 A：小鹅通管理台 + 公众号后台

| 操作 | 在哪做 |
|---|---|
| 新闻图文发布/编辑/会员权限 | 小鹅通管理台（图文 → 新建 → 设为会员专属） |
| 每月 4 次群发、自动回复、菜单 | 微信公众平台后台 |
| 会员列表、到期时间、订单、退款 | 小鹅通管理台 |
| 更新提醒推送 | 小鹅通内容更新提醒（自动） |

无开发，1 天可熟悉。

### 6.2 路径 C：自建 Admin（工作量约 3–5 天）

最小功能集：
- **内容管理**：新闻 CRUD（标题/摘要/富文本正文/标签/封面/发布时间/是否会员专属/定时发布）。
- **发布即推送**：点「发布」触发推送流水线（模板消息队列，限速下发，实时进度与失败列表）。
- **会员管理**：列表、搜索、到期时间、手动延期/赠送（客诉必备）、退订标记。
- **订单对账**：订单列表、与微信商户平台账单核对。
- **数据看板**：会员数/MRR/次日留存/单篇阅读 UV/付费墙拦截 → 转化率。

实现建议：Admin 用现成模板（如 react-admin / amis 搭建）+ 上述 5 组接口，不追求花哨。

## 7. 合规红线（上线前必读）

1. **「新闻」是特许行业**：依据《互联网新闻信息服务管理规定》，采编发布/转载**时政类新闻**需要网信办发放的《互联网新闻信息服务许可证》，一般企业拿不到。
   - **规避方式**：业务定位为**行业资讯/研究/情报/付费专栏**（如财经、科技行业分析），内容标注来源、不做时政采编。营业执照经营范围建议含「信息服务/企业管理咨询」。
   - 这是本业务最大的一个法律风险点，建议内容定位层面就避开时政新闻。
2. **模板消息**：禁止营销类群发（优惠、促销、降价类）；「文章更新通知」处于敏感区，靠「付费服务关系」支撑，控制频率、提供退订，避免用户投诉。
3. **ICP 备案**：大陆服务器必须备案；主体经营范围需匹配。
4. **iOS 虚拟支付**：上线前 iOS 真机实测，准备 Safari 兜底。
5. **诱导分享**：「分享解锁阅读」等玩法会被封，不要碰。

## 9. 下一步行动清单

**本周（无论选哪条路径）：**
1. 确认企业主体资质（营业执照、对公账户）。
2. 注册服务号 + 提交微信认证（300 元）。
3. 决策路径 A / C（建议：若 4 周内要见到付费用户 → A；若接受 1 个月建设期换长期低成本低抽成 → C）。

5. 内容合规自查：确认不涉时政采编，调整定位话术为「行业资讯/会员专享研究」。

**决策后：**
- 路径 A：开小鹅通专业版 + 超级会员 → 绑商户号 → 传首批内容 → 配菜单和自动回复 → 内测支付闭环 → 上线。
- 路径 C：按第 2/3/4/6 节实施，先做「支付 + 鉴权 + 内容页」最小闭环（MVP），Admin 和看板二期。
